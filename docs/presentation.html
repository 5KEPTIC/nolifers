Introduction — Problem Statement

Why unified personal media management?

Users consume media across multiple platforms (books, movies, anime, games, music) but data remains fragmented. No unified view, tracking, or cross-media recommendations.

  • Fragmented discovery
  • Lost personal context
  • Recommendation gaps

Goal: Build a unified media portal with centralized library, ratings, and multi-modal recommendation engine.

Key Outcome: Accurate, explainable recommendations based on cross-media history.

Database Architecture — Schema Design

Perfect Score: 5 Points

PostgreSQL relational schema with proper normalization, constraints, and relationships.

Core Tables: users, content_items, library_entries, ratings, recommendations, preferences
Normalization: 3NF design, minimal redundancy, single source of truth
Constraints: UUID primary keys, unique indexes, foreign key relationships with ON DELETE CASCADE
Data Types: Proper use of ENUM for controlled vocabularies, JSONB for flexible metadata

Database — Why PostgreSQL?

Advanced Features & Performance

  • Advanced Data Types: ENUM, JSONB, ARRAY, UUID
  • Full-Text Search: Built-in FTS for content discovery
  • Window Functions: For analytics and rankings
  • ACID Transactions: Data consistency guarantees
  • Indexing: B-tree, Hash, GiST indexes for query optimization
  • JSONB Operators: Flexible semi-structured data queries

Database — CRUD Operations

Create, Read, Update, Delete Patterns

CREATE:
INSERT INTO users (id, name, email) VALUES ($1, $2, $3)
READ:
SELECT * FROM content_items WHERE id = $1
UPDATE:
UPDATE library_entry SET status = $1 WHERE id = $2
DELETE:
DELETE FROM ratings WHERE id = $1
Critical: Use parameterized queries to prevent SQL injection. All queries must be ordered and validated.
Slide 8 of 17

Database — Advanced Queries & Analytics

Real-world Query Patterns

Monthly Completion Trends:

SELECT date_trunc('month', completed_on) AS month, COUNT(*) as count FROM library_entry WHERE status='completed' GROUP BY month ORDER BY month DESC

Average Rating per Content Type:

SELECT content_type, AVG(rating) as avg_rating, COUNT(*) as total FROM ratings JOIN content_items ON ratings.content_id = content_items.id GROUP BY content_type
